Ultima actualizacion: 22/08/2026

Este archivo se abre con el Bloc de notas. Imprimilo o llevalo en el pendrive.
La version larga de cada tema esta en docs/ del repositorio.


===============================================================================
REGLAS DE ORO  (leer SIEMPRE antes de salir)
===============================================================================

1) EL POS Y EL SERVIDOR TIENEN NUMERACIONES DISTINTAS.

      POS       ->  v0.1.24        (tags: v0.1.24)
      SERVIDOR  ->  servidor-v0.6.0 (tags: servidor-v0.6.0)

   NUNCA uses el numero del POS para el servidor. Ya paso: se compilo un
   instalador de servidor con el numero del POS (0.1.17) cuando el servidor
   iba por 0.4.0, se llevo a un cliente que tenia el 0.4.0, y fallo.

2) NUNCA compiles el instalador a mano con ISCC.
   Se publica siempre con el script, que ademas verifica el numero de version:

      .\scripts\release\publicar-instalador-servidor.ps1 -Version "0.7.0" -Notas "que cambio"

3) NUNCA instales una version mas vieja sobre una mas nueva.
   El codigo viejo queda contra una base de datos ya migrada por el nuevo, y
   las migraciones no se deshacen. Desde ahora el instalador lo frena solo y
   te avisa, pero fijate igual.

4) NUNCA copies la carpeta del proyecto por USB (node_modules son decenas de
   miles de archivos y falla a mitad). El pendrive es para los .exe.


===============================================================================
PASO 0 - ANTES DE SALIR (en tu PC, con internet)
===============================================================================

a) Fijate cual es la ULTIMA version publicada de cada cosa:

      gh release list --repo nexosoftfsa/nexosoft-pos-releases --limit 10

   Anotalas aca antes de salir:

      Servidor que llevo: servidor-v ______      POS que llevo: v ______

b) Bajate los dos instaladores de esas versiones y ponelos en el pendrive:

      NexoSoft-Servidor-<VERSION>-Setup.exe
      NexoSoft POS_<VERSION>_x64-setup.exe

   Estan en:
      https://github.com/nexosoftfsa/nexosoft-pos-releases/releases

c) Si el cliente contrato ACCESO REMOTO, hace los pasos 1, 2 y 3 de la
   seccion "ACCESO REMOTO" de mas abajo y anotate el codigo de activacion.

d) Llevate tambien en el pendrive, por las dudas:
      - WebView2 Runtime (si la PC es vieja o sin internet)
      - Este instructivo


===============================================================================
PASO 1 - INSTALAR EL SERVIDOR (solo en la PC de CAJA)
===============================================================================

El servidor va UNA SOLA VEZ, en la PC de Caja. Deposito y Oficina NO llevan
servidor, solo el POS.

1) Ejecutar NexoSoft-Servidor-<VERSION>-Setup.exe  (pide permiso de admin)

2) El asistente pide, en este orden:

      - Nombre del comercio        (aparece en el panel y en los tickets)
      - Usuario ADMIN + contraseña -> ANOTALA

        OJO CON ESTA CONTRASEÑA. El instalador acepta 8 caracteres, pero si
        el comercio va a tener ACCESO REMOTO esa clave queda siendo lo unico
        que separa a un desconocido de sus datos. Elegila VOS, no la dejes a
        criterio del dueño:
           - 12 caracteres o mas
           - que NO tenga el nombre del comercio (es lo primero que prueban)
           - que no sean todos numeros
        El POS avisa solo si detecta una contraseña floja.
      - Puerto de PostgreSQL       (dejar 5432; si la PC YA tiene otro
                                    PostgreSQL instalado, poner 5433)
      - Codigo de acceso remoto    (opcional; dejar vacio si no lo contrato)

3) Tarda VARIOS MINUTOS y muestra una consola negra. Es normal. No la cierres.

4) Al terminar, la ultima pantalla muestra la IP de esa PC. ANOTALA:

      IP de la Caja: ____________________

5) VERIFICAR antes de seguir. En el navegador de esa PC:

      http://localhost:3000/api/v1/health

   Tiene que decir:  {"status":"ok"}

   Si no dice eso, NO SIGAS. Ver la seccion SI ALGO FALLA.


===============================================================================
PASO 2 - INSTALAR EL POS (en cada PC: Caja, Deposito, Oficina)
===============================================================================

1) Ejecutar "NexoSoft POS_<VERSION>_x64-setup.exe"  (no pide admin)

2) La primera vez que abre, en Configuracion cargar:

      Servidor de sucursal:
         En la CAJA               ->  http://localhost:3000/api/v1
         En DEPOSITO u OFICINA    ->  http://<IP-de-la-caja>:3000/api/v1

      Razon social, CUIT, condicion IVA, punto de venta, LOGO.

      "Ya esta de alta en ARCA"  ->  DEJAR DESTILDADO salvo que el comercio
                                     ya facture con CAE.

3) Elegir o crear la terminal ("Caja 1", "Deposito", "Oficina") con el boton
   "+ Agregar" de esa misma pantalla.

4) Entrar con el usuario ADMIN que creaste en el Paso 1.


===============================================================================
PASO 3 - CATALOGO REAL
===============================================================================

Se hace DESDE EL POS, no por linea de comandos:

   POS -> Catalogo -> boton "Importar articulos"  ->  elegir el Excel

   1) Primero con la opcion de PRUEBA (dry-run) tildada: muestra que va a
      pasar sin tocar nada. Revisar que no haya sorpresas.
   2) Despues destildarla y confirmar.

Al terminar, contar los articulos y comparar con el Excel.

OJO: el comando "pnpm importar:catalogo" que figura en la guia vieja
(docs/instalacion-primer-cliente.md) SOLO funciona si el servidor se instalo
clonando el repositorio. Con el instalador (C:\NexoSoft-Servidor) ese script
no existe: usar el POS.

===============================================================================

   [ ] Una venta de prueba completa
   [ ] Imprimir el ticket chico
   [ ] Imprimir el A4

===============================================================================
ACCESO REMOTO  (ver el panel desde afuera del local) - OPCIONAL
===============================================================================

Cada comercio queda en https://<comercio>.nexosoft.com.ar
Los pasos 0 y 1 son EN TU PC, antes de salir. El 2 es en la PC del cliente.

NO entres a Cloudflare Zero Trust: te va a pedir una tarjeta de credito aunque
el plan sea gratis, y no hace falta. Todo esto se hace por linea de comandos
con tu cuenta normal de Cloudflare.

0) UNA SOLA VEZ, la primera vez que hagas esto en tu PC:

      cloudflared tunnel login

   Abre el navegador: elegir nexosoft.com.ar y autorizar.
   Deja %USERPROFILE%\.cloudflared\cert.pem  ->  ESO ES UN SECRETO TUYO.
   No lo subas a ningun lado ni lo copies a la PC de un cliente.

   (Si no tenes cloudflared: sale de
    .\scripts\release\preparar-runtimes-instalador.ps1)

1) POR CADA COMERCIO, un solo comando en tu PC:

      .\scripts\release\generar-codigo-acceso-remoto.ps1 -Subdominio lagus

   Crea el tunel, apunta lagus.nexosoft.com.ar al tunel, y te devuelve UN
   SOLO texto largo: ese es el codigo de activacion.

   OJO: un solo nivel de subdominio. lagus.nexosoft.com.ar SI.
        panel.lagus.nexosoft.com.ar NO (falla el certificado).

   Mandaselo SOLO a ese comercio: quien lo tenga puede levantar su tunel.

2) En la PC del cliente, cualquiera de las dos:

      - Durante la instalacion: pegarlo en la pantalla "Acceso remoto".
      - Despues: en el POS -> Configuracion -> Acceso remoto -> pegar y
        "Activar". Windows pide permiso de administrador una vez.

3) VERIFICAR: en el POS, la tarjeta de Acceso remoto tiene que decir
   "Se esta viendo bien desde afuera", y ahi mismo aparece el QR.
   Probar la direccion desde un celular CON DATOS MOVILES (no el wifi
   del local).

   Si la tarjeta muestra un aviso NARANJA o ROJO de contraseñas flojas,
   arreglalo ANTES de irte: entra a Usuarios y cambiales la clave. Con el
   panel publicado en internet, esa contraseña es la unica puerta.
   Regla: 12 caracteres o mas, sin el nombre del comercio, no todo numeros.

QUE SE PUEDE HACER DESDE AFUERA (para explicarselo al cliente)
--------------------------------------------------------------

Desde afuera del local el sistema es de SOLO LECTURA: se entra al panel y se
miran los reportes. NO se puede vender, ni cambiar precios, ni tocar usuarios.
Eso es a proposito:

  - Si le roban la contraseña, el que entre solo ve reportes. No puede
    hacer daño.
  - El dueño tampoco puede administrar desde el celular: para cambiar algo
    hay que estar en el local. Decíselo de entrada asi no se sorprende.
  - Cada ingreso desde afuera queda registrado (usuario, fecha e IP).

Para apagarlo: POS -> Configuracion -> Acceso remoto -> Desactivar.

Desde tu PC podes ver los tuneles de todos los comercios:

      cloudflared tunnel list
      cloudflared tunnel info nexosoft-lagus

DAR DE BAJA EL ACCESO REMOTO DE UN COMERCIO (son 3 pasos, no 1)
---------------------------------------------------------------

1) En la PC del comercio: POS -> Configuracion -> Acceso remoto -> Desactivar
   (o el script con -Accion desactivar)

2) Borrar el tunel, desde tu PC:

      cloudflared tunnel delete nexosoft-lagus

   Si dice "This tunnel has active connections", esperá un minuto o corré
   antes:  cloudflared tunnel cleanup nexosoft-lagus

3) Borrar el registro DNS A MANO. Borrar el tunel NO borra el subdominio:
   queda apuntando a la nada.

      Cloudflare -> menu izquierdo DNS -> "Archivos" (es "Records", la
      traduccion es mala) -> buscar la fila del subdominio del comercio
      (tipo CNAME, apunta a algo.cfargotunnel.com) -> Editar -> Eliminar


===============================================================================
ACTUALIZAR UN CLIENTE QUE YA TIENE NEXOSOFT
===============================================================================

EL POS se actualiza solo (avisa y pide reiniciar).

EL SERVIDOR: desde el POS de la PC de Caja ->
   Configuracion -> Actualizaciones -> "Actualizar servidor"

   - Solo aparece en la PC de Caja (la que aloja el servidor).
   - Pide confirmacion y despues Windows pide permiso de administrador.
   - HACERLO CON EL NEGOCIO CERRADO O SIN VENTAS ACTIVAS.
   - Tarda varios minutos y el servidor queda sin responder un rato.

El servidor tambien se actualiza SOLO todas las noches a las 04:00 y cada vez
que se prende la PC. Si algo sale mal, vuelve solo a la version anterior.

NO hace falta correr el instalador de nuevo para actualizar. El instalador es
para la PRIMERA instalacion.


===============================================================================
SI ALGO FALLA - DONDE MIRAR
===============================================================================

TODOS los logs estan en:   C:\ProgramData\NexoSoft\logs\

   bootstrap.log        -> la instalacion del servidor (Paso 1)
   actualizador.log     -> la actualizacion automatica del servidor
   acceso-remoto.log    -> el alta/baja del acceso remoto
   cloudflared.log      -> el tunel corriendo (si la direccion no responde)
   postgres.log         -> la base de datos

Abrilos con el Bloc de notas. El error real esta ahi, casi siempre en las
ultimas lineas.

Comandos utiles (PowerShell como Administrador, en la PC de Caja):

   # ¿Estan corriendo las tareas del servidor?
   Get-ScheduledTask -TaskName "NexoSoft*" | Get-ScheduledTaskInfo

   # Arrancar el servidor a mano
   Start-ScheduledTask -TaskName "NexoSoft cloud-api"

   # ¿Esta el tunel corriendo?
   Get-ScheduledTask -TaskName "NexoSoft Acceso Remoto" | Get-ScheduledTaskInfo

   # Estado del acceso remoto
   C:\NexoSoft-Servidor\scripts\instalar-acceso-remoto.ps1 -Accion estado

   # Que version de servidor hay instalada
   Get-Content C:\NexoSoft-Servidor\dist-servidor\VERSION


PROBLEMAS CONOCIDOS
-------------------

* "El health no responde / no abre el panel"
  -> Mirar bootstrap.log. Casi siempre es el puerto 5432 ocupado por otro
     PostgreSQL que ya estaba en la PC: reinstalar eligiendo 5433.

* "El instalador dice que ya hay una version mas nueva instalada"
  -> Estas por instalar un servidor MAS VIEJO. Conseguí el instalador de la
     ultima version del SERVIDOR (ojo: no es el numero del POS).

* "Deposito u Oficina no ven el servidor"
  -> Revisar que pusiste http://<IP-de-la-caja>:3000/api/v1 (no localhost),
     que las dos PC estan en la misma red, y que el firewall de la Caja tiene
     la regla (la crea el instalador; se rehace con
     C:\NexoSoft-Servidor\scripts\abrir-firewall-servidor.ps1).

* "La direccion de afuera no responde"
  -> Que la PC tenga internet y que la tarea "NexoSoft Acceso Remoto" este
     corriendo. El detalle esta en logs\cloudflared.log. Desde tu PC,
     "cloudflared tunnel info nexosoft-<comercio>" dice si el tunel tiene
     conexiones activas.
